## 勘误（2026-10-17 02:15，Claude）：音色和空间指标的技术验收**撤回**

P1a 核对 Rust 核心时发现，P0 样片并不是渲染引擎的直接输出：`run_p0.py` 在等响度匹配阶段调用了 `equal_loudness_timbre()` → `timbre_guard()`，**逐个文件**把效果版本的 1/3 倍频程形状拉向原声，单个频带最多修正 ±18 dB。这一步在引擎之外，依赖整段原声作为参照，没法实时运行，Rust 核心里也没有它。

Claude 当时测的是经过这一步处理后的样片，所以上文 D2／D8 的"40 Hz–16 kHz 偏差在 ±3 dB 以内"和强度曲线的结论，都**不能代表引擎本身**。重新测量引擎的直接输出（路线 B，强度 0.4，KU100，正前方均衡；脚本 `qa/tools/raw_engine_vs_dry.py`），结果如下：

| 素材 | 原声 IACC | 引擎 IACC | 超出 ±3 dB 的频带（去掉整体电平差） |
|---|---:|---:|---|
| 音乐 | 0.594 | 0.590（**几乎没有展宽**） | 630 Hz −4.6；1–2 kHz +3.5；10–16 kHz **+6 到 +9** |
| 人声 | 0.970 | 0.933 | 无 |
| 环境音 | 0.288 | 0.141 | 2.5–6.3 kHz +3.3 到 +4.7；16 kHz +12.3 |

处理：

1. P0 听感样片**作废**，`qa/p0/listening/` 标记为不可用。
2. 由 Cursor 按 P0-cursor-04 修订：音色校正必须放进引擎，并且对每个 HRTF 和预设是固定的（不能依赖原声）；音乐需要有真实可测的展宽；样片除了单一增益的响度匹配外，不允许任何后处理。
3. 验收流程补一条：Claude 以后对引擎的指标，一律用自己的脚本直接调用引擎测量，不再使用代理产出的样片作为测量对象。
