# P0-cursor-04：音色校正放进引擎，音乐展宽

测量日期：2026-10-17。分支 `agent/cursor/P0-02`。种子 `20261016`，48 kHz，块长 256，路线 B，预设 `room`，正前方均衡，方向功率补偿开。

指标全部来自 `Processor.process_file` 的直接输出，对照原声，没有响度匹配，也没有 `diagnostic_timbre_guard`。算法与 `qa/tools/raw_engine_vs_dry.py` 相同，入口是 `qa/tools/measure_raw_engine.py`。每个 1/3 倍频程的数值在 `qa/p0/cursor/metrics_v2.json`。下表的「最大偏差」是 40 Hz–16 kHz、去掉整体电平差之后的绝对值最大者。门限是 `> 3.0 dB` 才算超出，所以 3.00 通过。

IACC 是 ±1 ms 内归一化互相关的峰值，不减均值，与 `qa/tools/p0_metrics.py` 一致。

## 2. 勘误里的引擎，拆开看

`qa/p0/ACCEPTANCE-cursor-03.md` 末尾的勘误测的是旧路线 B：Schroeder 全通做侧向去相关，没有固定均衡。音乐强度 0.4、KU100、正前方均衡时，整段 IACC 0.590（原声 0.594），10–16 kHz 偏亮 6–9 dB。同一设置下把各支路单独听完，能量比例和相对原声的电平是：

| 支路 | 能量占比 | IACC | 相对整段电平 |
|---|---:|---:|---:|
| 直达对象 | 0.876 | 0.595 | −2.5 dB |
| 宽像一对 | 0.086 | 0.626 | −13.5 dB |
| 后方环境 | 0.038 | 0.564 | −19.4 dB |
| 侧向 L−R | — | 0.574 | −1.8 dB |
| 早期反射 | — | 0.542 | −34.7 dB |
| FDN | — | 0.269 | −51.8 dB |
| 150 Hz 以下旁路 | — | 1.000 | −20.8 dB |

音乐大约 88% 被判成直达。单点 HRTF 的宽带 IACC 在每个方位都接近 1（耳间延时落在 ±1 ms 里面），左右对称的相干扇区加起来也是 1。把扇区张得更开不会降低宽带 IACC。环境比例只是在那约 12% 的非相干残余里重新分配，所以把它拉满也不展宽。早期反射和 FDN 低 30 dB 以上，听不见。

侧向全通级联之后，侧向总线自己的 IACC 仍有 0.574，而且它只比直达低 1.8 dB。±1 ms 的互相关窗口看不出全通的相位扩散。音乐侧向能量大多在 500 Hz–2 kHz，这段的自相关在 5 ms 和 8 ms 有峰。换成落在这些峰旁边的纯延时（预设里的 `decorrelator_delays_ms`）之后，侧向才真正掉到窗口外面。强度 0.8 时直达仍占 0.84，整段 IACC 只到 0.560，离「比原声低 0.15」还差一截。

人声强度 0.4 的直达占 0.994，侧向低约 15 dB，整段 IACC 约 0.933，中置本来就是稳的。相干性门限不能再抬：人声和音乐的平均相干性很接近（约 0.72 对 0.64），抬门限会把人声漏到侧向。

环境音强度 0.4 几乎不走直达（占比 0.15），宽像 0.59、后方 0.26，IACC 0.141。偏亮的是 2.5–6.3 kHz（约 +3 到 +4.7 dB）和 16 kHz（+12 dB）。

## 3. 高频「偏亮」里有两个假象

整文件、不加窗的 rfft 会被文件头尾的不连续主导，而音乐在 14–18 kHz 几乎没有真实能量。两处实现问题把这个读数抬了上去：

- 上混重叠相加在文件开头除以不完整的窗和。稳态的 Hann 重叠和是满的，开头只有 `hann` 的第一个采样那么小。频谱一旦被掩码改过，逆变换在窗边不再接近 0，这一除就把大约第 1049 个采样（STFT 延迟 1024 加上 HRIR 峰）放大成一个点击。KU100 音乐效果版本的高频能量有大约九成在开头 30 ms。未改频谱的恒等掩码看不出这个问题，因为原来的短时变换在窗边已经是 0。修复是除数改为 `max(窗和, 稳态窗和)`，稳态不变，边缘保持自然淡出。
- `delay_buffer` 在开头补零、把尾巴丢掉，最后一个采样变了。只把干声音乐最后 64 个采样清掉，16 kHz 的读数就会动大约 5 dB。输出最后 128 个采样交叉淡回 `输入 × DRR 增益`，端点恢复。这是固定长度，不是按文件去配音色。

这两处修完之后，粉红噪声过引擎的 1/3 倍频程误差在 0.7 dB 以内，没有高频架子。勘误里那 +6 到 +12 dB 不能再用一条粉噪逆滤波器去对。

另外一处电平错误：高通图像乘了 DRR 增益，150 Hz 以下的旁路没有乘。强度 0.8 的 DRR 是 −4.8 dB，去掉中位数之后低音看起来高 4 dB。旁路现在乘同一个增益。

## 4. 固定的空间参数

公共均衡只能给所有素材加同一个增益。某个 1/3 倍频程上，最亮和最暗的素材如果相差超过 6 dB，就不存在一条增益能让它们同时落进 ±3 dB。所以先改支路，再设计均衡。这些参数只看 HRTF、预设和频率，不看节目。

- `hf_pan_floor = 0`。3–8 kHz 的直达扇区收到正前。展宽靠的是 2 kHz 以下的侧向延时，不靠把高频扇区撑开。
- `hf_direct_start_hz = 4000`，`hf_direct_end_hz = 8000`。掩码在这之间收到正前直达，能量和仍是 1。侧向 HRTF 的单声道下混会把安静的最高一个八度压暗；人声在那里本来就在中间。斜坡只是频率的函数。
- `bed_peak_db = 6`，1–1.6 kHz，只加在宽像和后方床层上。环境音的 1.25 kHz 在床层上，音乐的直达几乎不经过这里。不随强度缩放。
- `side_lpf_hz = 6000`。侧向馈送做零相位升余弦淡出：5.5 kHz 以下是平的，6.5 kHz 以上没有了。环境音的 8 kHz 偏亮主要来自这条没经过 HRTF 的侧向。最小相位低通会把耳间延时拉回 ±1 ms 里面，展宽消失，所以必须是零相位。
- 房间预设的侧向增益从 0.630 到 1.374，随强度线性插值。固定均衡会抬那些更相干的频带，宽带 IACC 会少掉大约 0.04。增益留了这一截。

包围感和环绕预设写了同一组高频和床层参数。它们的 `fixed_eq` 还没有设计，本报告的表只覆盖 `room`。

## 5. 固定均衡

运行时是 512 点最小相位 FIR，左右耳同一条，接在混音和端点交叉之后。系数来自预设里的 1/3 倍频程增益，按 HRTF 和强度各存一行，中间强度在 dB 上线性插值。设计在 `qa/tools/design_fixed_eq.py`：

1. 探针是 4 秒粉噪：双单声道、相关系数约 0.6、完全不相关。都不是交付文件。目标增益是这三条中位数去除后的平均误差的相反数，限制在 ±6 dB。
2. 三条真实素材是约束，不是目标。某个频带只有在粉噪逆滤波会把其中一条推出 ±2.85 dB 时才离开粉噪曲线，而且只移到刚好把三条都收回去的位置。三条已经张得比 5.7 dB 更开时，增益取最亮和最暗的中点。
3. `--adjust` 再渲染带均衡的文件，把剩余误差补进同一条曲线，最多两轮。运行时滤波器仍然不看输入。

复现：

```bash
prototypes/.venv/bin/python qa/tools/design_fixed_eq.py room
prototypes/.venv/bin/python qa/tools/design_fixed_eq.py room --adjust
```

`diagnostic_equal_loudness_timbre` 和 `diagnostic_timbre_guard` 还在，注释写明不能用于样片或报告指标。它们按整段原声拟合，不能实时。
