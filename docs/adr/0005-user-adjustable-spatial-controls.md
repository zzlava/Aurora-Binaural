# ADR 0005：成品 App 提供手动调节空间感的控件

日期：2026-10-17
状态：已接受（用户："我希望在成品 app 里可以手动调节空间感"）

## 决定

在预设（默认 V3）的基础上，向用户提供 **5 个宏控件**，取值都是 0–1，在 GUI、CLI 和 API 中统一使用。每个宏控件映射到路线 V 的若干内部参数，映射关系写在 `presets/route_v.toml` 里，可以调整，不写死在代码中：

| 控件（界面名称） | 键名 | 主要影响的内部参数 |
|---|---|---|
| 空间强度 | `strength` | 现有的强度映射（整体缩放） |
| 声场宽度 | `width` | `front_az`（约 30–60°）、宽声场和环绕的增益 |
| 头顶感 | `height` | 高度层增益、`height_el`、天花板反射的电平 |
| 房间感 | `room` | `room_db`（直达混响比）、`t60` |
| 人声距离 | `voice_distance` | `direct_room_send_db`、`center_distance_m`（0 为最近） |

- 预设只是一组宏控件取值的起点。用户调过以后，可以保存为"我的预设"（GUI 保存在本地，API 通过参数传入）。
- Rust 核心必须支持在运行中修改这些参数：参数平滑，不分配内存，不出现爆音；这也是将来实时处理的前提。
- 试听、导出、API 任务的报告中，都要记录实际使用的宏控件取值和展开后的内部参数，保证结果可以复现。
- 安全范围：每个宏控件在映射表里设置上下限，防止用户调出削波或音色严重失真的结果；限制器始终开启。
