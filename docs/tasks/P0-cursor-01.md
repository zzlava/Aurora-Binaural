## 目标

用 Python 实现三条渲染路线的离线原型，在同一组素材上对比，为 P1 的 Rust 核心选定算法路线和 HRTF 数据集：

- **A. 虚拟扬声器**：立体声 → ±30° 两个虚拟扬声器 → HRTF + 小房间
- **B. 上混 + HRTF**：STFT 直达／环境分离 → 直达成分按估计方位做 HRTF 渲染，环境成分去相关后放到侧后方 + 房间
- **C. 上混 + Ambisonics**：同 B，但环境成分、早期反射和环绕运动都走 3 阶 Ambisonics + MagLS 双耳解码

三条路线的共同要求：

- 低频旁路（分频点约 120–200 Hz，互补滤波器）
- HRTF 均衡：对比扩散场均衡与正前方均衡两种做法
- 强度参数按 plan 6.8 节映射，**禁止用干湿混合实现**；`strength=0` 时完全旁路
- 早期反射用鞋盒镜像源法；晚期混响用 FDN；所有随机量都由显式 seed 生成
- 坐标遵循 plan 6.9 节（+X 前、+Y 左、+Z 上，方位角向左为正）
- 处理按块进行（例如 512 帧一块），并提供"块大小一致性"测试，为 P1 的实时安全核心做准备

## 环境

- 用 uv 在 `prototypes/` 内建立隔离环境（`prototypes/.venv` 已被 git 忽略），锁定依赖（`uv.lock`）。不要修改全局 Python。
- 可以使用 numpy、scipy、soundfile、sofar、spaudiopy、pyfar、pyloudnorm 或等效库；在报告里写明版本和许可证。
- 响度和真峰值使用 BS.1770 方法（pyloudnorm，或 ffmpeg 的 ebur128 滤镜）；真峰值要 4 倍过采样。

## HRTF 数据

- 至少对比两个实测数据集（例如 TH Köln KU100、SADIE II），从官方来源下载。
- 在 `data/hrtf/SOURCES.md` 中记录：来源 URL、版本、许可证原文链接、SHA-256、采样率、方向数量。
- `.sofa` 文件通过 Git LFS 提交（`.gitattributes` 已配置）。单个文件超过 100 MB 时，先在报告里说明，不要提交。
- 缺少数据时直接报错，**不允许**回退到合成数据。
