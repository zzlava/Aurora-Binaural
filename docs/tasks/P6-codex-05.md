# P6-codex-05：导出响度选项（N2 决定：默认 D 峰值归一化）与小修

状态：已派发（2026-10-18）
执行方：Codex　分支：`agent/codex/P6-05`（基于最新 main，已含 P1d）
时间上限 120 分钟；每完成一个子项就先提交一次。不改 core/、presets/、tools/、qa/tools/、prototypes/。

## 背景
用户已决定 N2（见 docs/DECISIONS-PENDING.md）。实测：《泡沫》原曲 −13.2 LUFS / −2.7 dBTP，V3 导出为 −21.8 LUFS / −6.3 dBTP；《卡门》原曲 −25.4 / −3.8，V3 导出为 −32.2 / −9.6。核心的输入余量是固定值，导出时有大量浪费的余量。

## 任务
1. **导出响度模式** `loudness`（CLI `--loudness`，API 字段，GUI 导出面板下拉框，“我的预设”可以保存）：
   - `peak`（**默认**，GUI 文案“智能音量（推荐）”）：渲染完成后测量整段的真峰值（ITU-R BS.1770 4 倍过采样），再施加**一个固定增益**，使真峰值 = −1.0 dBTP。这一步不经过限幅器，也不做动态处理。增益只做提升，不做衰减（如果真峰值已经 > −1 dBTP，则不变，并在报告中记录）；提升上限 +20 dB。
   - `match`（“匹配原曲响度”）：使用固定增益让 integrated LUFS 等于源文件；超出 −1 dBTP 的部分交给真峰值限幅器（复用现有的应用层或编码前限幅器；若核心限幅器不能单独调用，用应用层实现 lookahead 真峰值限幅，并写明它会压缩低频）。报告中写明限幅器的最大增益衰减。
   - `lufs14`（“流媒体 −14 LUFS”）：同 match，但目标为 −14 LUFS。
   - `off`（“不调整”）：保持引擎原样输出。
   - 顺序：渲染 → 响度增益/限幅 → 采样率转换 → 位深/TPDF 抖动 → 编码。真峰值在最终采样率下复核，若因重采样超出 −1 dBTP，再整体回退相应增益。
   - render report 增加：loudness_mode、applied_gain_db、output_lufs、output_true_peak_dbtp、limiter_max_gr_db。
   - 试听片段与 A/B 不变（继续做等响度匹配）；整段导出才执行 loudness 模式。批量处理时每个文件分别计算。
   - 两遍处理不得把整段音频重复放进内存：大文件（≥ 30 分钟、192 kHz）要用分块或临时文件实现，并测量内存峰值写入报告。
2. **重复的“空间强度”滑块**：主滑块和高级面板中的滑块合并为一个（推荐只保留主滑块，高级面板显示其他 4 个），或者两者双向联动。补上相应的 Playwright 测试。
3. **测试**：pytest 覆盖 4 种模式下的增益与真峰值（容差 ±0.1 dB）、“只提升不衰减”、+20 dB 上限、重采样后的复核、16 bit 抖动在增益之后执行、报告字段、“我的预设”保存 loudness。另做一个 GUI e2e：导出一段响度母带，确认真峰值为 −1.0±0.1 dBTP。
4. **文档**：在 docs/user/quickstart.md、cli.md、api.md 中加入导出响度一节，说明 4 种模式的取舍（peak 不压缩、match/lufs14 可能压低频）。
